# Модуль 07: Агенти та багатоагентні системи — Лабораторна робота

> **Статус:** Ready for Students — затверджено викладачем для публікації 2026-11-20

## Мета

Мета цієї лабораторної роботи:

1. Закриття прогалини фіксованого шляху у виборі наступної дозволеної операції відповідно до повернутої інформації.
2. Виконання придатного до інспектування **циклу агента** лише для читання.
3. Оцінювання виконання завдання, якості відповіді та використання ресурсів для адаптивного й фіксованого шляхів за оголошених умов порівняння.

## Завдання

1. Виконати обраний моделлю інформаційний запит та інспектувати рішення застосунку щодо дозволу й фактичне читання.
2. Продовжити те саме завдання через допуск свідчень, керований моделлю вибір операцій, повернуті спостереження та обмежену зупинку.
3. Виконати заздалегідь визначене продовження з того самого збереженого читання, незалежно оцінити фактичні відповіді та інтерпретувати спостереження ресурсів за спільних умов.
4. Виконати контрольовані перевірки відмови в дозволі, збереження свідчень на відміну від їх передавання та перерваного виклику без додаткових платних викликів моделі.
5. Завершити україномовний звіт-джерело, зберегти потрібні знімки екрана, перевірити точний остаточний коміт студента й підготувати самодостатній звіт для Teams.

## Очікуваний результат

Завершений маршрут залишає такі придатні до інспектування артефакти в `reports/lab07/`:

- `first-read/` — фактична перша дія, рішення щодо дозволу, виконаний запит і повернуті кандидати або збережений результат зупинки.
- `adaptive/` — обмежене адаптивне продовження, допущені свідчення, фактичні запити, відповіді та передавання інформації про перебіг завдання.
- `fixed/` — заздалегідь визначене продовження з того самого першого читання зі збереженням фактичного генерування або збою.
- `boundaries/` — явно контрольовані діагностичні фіксації та їхнє зведення, якщо їх завершено.
- `REPORT.md` і `screenshots/` — незалежні судження студента, інтерпретація ресурсів, межа зупинки та власні знімки контрольних точок.
- `verification-report.json` — перевірка точного остаточного коміту з розрізненням повного й чесно часткового записів.
- `submission/REPORT.md` — згенерований україномовний звіт для Teams із вбудованими зображеннями досягнутих контрольних точок, а не вихідний артефакт Git.

Незавершена або несприятлива спроба зберігається, а не замінюється. Успішна команда або зупинка моделі не є сприятливим людським судженням про відповідь, доказом виконання завдання чи дозволом на запис до канонічних даних.

## Вихідний стан

Навчальний приклад застосовує загальний підхід до керування, щоб пояснити, чому **ембединг запиту** потрібен для **пошуку на основі ембедингів**. Курс надає синтетичний ресурс із двох уривків `cases/lab07/accessible-passages.json`, а не ще одну зміну прийнятої колекції чи завдання підготовки графа. Початковий запит надає AP-1, який називає передумову; модель не повинна отримати AP-2 лише тому, що людина може інспектувати джерельний ресурс.

Студент виконує фактичний маршрут і окремо діє як **оцінювач-людина**. Застосунок відповідає за доступ до джерел, допуск, перевірки дозволів, виклик, передавання спостережень та обмеження зупинки. **Канонічна колекція знань** залишається незмінною. Звіти й виходи середовища виконання в робочому просторі не є прийнятими знаннями. Експеримент не реалізує **багатоагентну систему** чи інший алгоритм інформаційного пошуку.

Усі наведені нижче команди виконуються із синхронізованого каталогу `training-project`. Замініть `<student-id>` особистим ідентифікатором гілки; перед ініціалізацією створіть цю гілку за процедурою Git курсу. Не починайте виконання моделі до створення звіту-джерела.

### Призначення та межа

Студент починає одне завдання пояснення передумови: пояснити, чому **ембединг запиту** потрібен для **пошуку на основі ембедингів** у навчальному маршруті. Початковий уривок називає передумову, не пояснюючи ролі цього представлення. Модель обирає наступну дію; код застосунку вирішує, чи дозволений запит, і виконує дозволену **операцію інформаційного пошуку**.

Крок студента 1 зупиняється після повернення операцією кандидатних уривків. Ці кандидатні уривки ще не пройшли **відбір одиниць інформаційного пошуку**, не були передані в іншому **обмеженому запиті до моделі** та не становлять згенерованої відповіді. Подальші кроки продовжують те саме завдання, а не починають незалежні вправи за розділами.

### Входи та відповідальність

Студент починає з накопичувального `training-project` із підтримуваним середовищем `uv` із лабораторних робіт 01–06. Студентові потрібен автентифікований доступ до AGY з доступною безоплатною квотою. Приклад використовує наразі перевірений ідентифікатор моделі `gemini-3.8-flash-low`; перед виконанням `agy models` має вивести цей ідентифікатор. Успішний запит каталогу не доводить наявності залишку квоти чи вільної потужності моделі. Команда вимикає згоду на використання платних кредитів через `useG1Credits: false`; за вичерпання квоти студент має зупинитися, а не купувати кредити для вправи.

Курс надає `cases/lab07/accessible-passages.json` — синтетичний джерельний ресурс лише для читання з ідентифікатором `S-AGENT/v1`. Уривки конкретизують підрозділ 1.3 модуля 07; цей ресурс не є зміною **канонічної колекції знань**, прийнятої в лабораторній роботі 06.

- `AP-1`, джерело `S-AGENT`, версія `v1`, уривок 1: “In this teaching route, understanding embedding-based retrieval requires understanding a query embedding.”
- `AP-2`, джерело `S-AGENT`, версія `v1`, уривок 2: “A query embedding represents the question as a vector for comparison with stored vectors representing retrieval units. Understanding that representation explains how the question can be matched to candidate retrieval units.”

Застосунок спочатку допускає лише `AP-1` як **надані джерельні свідчення**. `AP-2` залишається доступним для операції інформаційного пошуку, але відсутній у запиті вибору дії. Заданий курсом допуск зафіксовано для початкового запиту; цей крок не вимагає від студента затверджувати нові знання.

**Перелік доступних інструментів** надає дві операції:

- **Операція інформаційного пошуку** приймає непорожній `text query` та `collection`, що дорівнює `S-AGENT/v1`. Застосунок шукає у двох джерельних уривках установленим у лабораторній роботі 04 методом лексичного перекриття, зберігаючи вказівки на місця в джерелі. Предмет пояснення — пошук на основі ембедингів; метод пошуку для отримання свідчень цього пояснення — лексичний пошук.
- **Операція пояснення передумов із використанням моделі** приймає порожні аргументи; код застосунку побудував би запит цієї операції з допущених свідчень. Крок студента 2 може виконати цю операцію після допуску свідчень.

Модель також може запропонувати `stop` з порожніми аргументами. Студент спостерігає фактичний вибір, не замінюючи несприятливий вибір. Фіксовану область джерел забезпечує застосунок, а не модель чи студент. Обрані моделлю шляхи, команди оболонки та записи до канонічних даних не є виконуваними входами.

### Крок студента 1 — Виконати та інспектувати першу дію

Із `training-project` виконайте такі команди у Windows PowerShell або терміналі Linux/macOS:

```text
agy models
uv run learning-project lab07 run-first-action --model gemini-3.8-flash-low --output-dir reports/lab07/first-read
```

Команда резервує спробу, яку можна лише створити, та записує точний **обмежений запит до моделі** для вибору дії перед викликом AGY. Три поля запиту — `task instruction`, `supplied source evidence` та `output contract`. Схема операцій є частиною контракту виходу, а не окремим викликом AGY для виправлення схеми. Модель повертає запропоновану дію; код застосунку виконує дозволений пошук. Жоден виклик інструмента моделлю не виконує пошук безпосередньо.

Відкрийте згенеровані файли в редакторі:

- `attempt.json` фіксує запитувані адаптер і модель, версію джерела та режим отримання.
- `request.json` зберігає початкове завдання, описи операцій, початкові свідчення `AP-1` та контракт виходу дії.
- `provider-response.json` зберігає повні stdout, stderr і код завершення процесу, зокрема оболонку відповіді постачальника та повідомлене використання ресурсів, коли вони наявні.
- `action.json` зберігає єдиний видобутий запит дії.
- `trace.json` відокремлює запитувану дію, рішення щодо дозволу, виконані входи та **ранжований кандидатний вихід**.
- `run-metadata.json` фіксує спостережений статус і тривалість процесу постачальника; `semantic_judgment` залишається `not performed`.

**Спостережений результат нормального шляху:** `status` має значення `candidates returned`; запитувана операція — `retrieval operation`, рішення щодо дозволу є позитивним, а `executed input` дорівнює фактичному запиту моделі та `S-AGENT/v1`. Інший живий запит моделі може дати інше ранжування або не дати кандидатів. Ані спостережений порядок, ані точний запит не є обов’язковим сприятливим вибором моделі.

Студент перевіряє, що:

1. `request.json` містить лише `AP-1` як надані джерельні свідчення; пояснювальний текст `AP-2` відсутній.
2. Запит дії називає операцію та точні аргументи; рішення щодо дозволу є окремим результатом застосунку.
3. Ідентифікатор і текст кожного повернутого кандидата відповідають наданому ресурсу, а вказівка на місце в джерелі вказує на відповідний уривок цього ресурсу. Лексичний бал не є людським судженням про підкріплення.
4. `delivered to next model request` має значення `false`, а `next_model_request_count` дорівнює нулю. Нове пояснення чи сприятливе судження про виконання завдання не заявляються.

Зафіксуйте `01-model-selected-read.png`, показавши запитувану дію, наданий дозвіл, виконаний запит, повернуті ідентифікатори та вказівки на місця в джерелі й межу без наступного запиту. Збережіть згенеровані файли та знімок екрана для подальшого маршруту звіту; не редагуйте свідчення постачальника та не вважайте знімок екрана заміною машинозчитуваної траси.

Якщо команда завершується збоєм, виходи вже існують, у дозволі відмовлено, модель пропонує зупинитися, модель запитує операцію пояснення, яку цей крок не виконує або пошук не повертає кандидатів, зупиніться та збережіть фактичні наявні свідчення. Не перезаписуйте спробу, не перейменовуйте операцію та не підставляйте заздалегідь визначений запит, щоб штучно отримати нормальний шлях. Збій виконання постачальника не є **відмовою** операції пояснення передумов. Навіть нормально повернений непорожній список кандидатів не доводить завершення початкового завдання.

### Призначення та межа

Студент продовжує початкове завдання: пояснити, чому **ембединг запиту** потрібен для **пошуку на основі ембедингів** у навчальному маршруті. Попереднє читання повернуло кандидатів, але не передало ще одного запиту моделі. Тепер застосунок допускає придатні уривки, передає наступний **обмежений запит до моделі** для вибору дії, виконує дозволену запитувану операцію та повертає результат операції до подальшого рішення. **Цикл агента** закінчується за пропозицією моделі зупинитися або за обмеженням, яке забезпечує застосунок, а не автоматичним сприятливим судженням.

### Входи та обмеження застосунку

Використайте завершений `reports/lab07/first-read` із кроку студента 1 і незмінний ресурс курсу `cases/lab07/accessible-passages.json`. Продовжуйте лише після того, як перевірки першого читання встановлять `candidates returned` і непорожній список кандидатів. Продовження перевіряє збережені запит, дію та трасу, відтворюючи зафіксовану відповідь відносно ресурсу курсу без виклику постачальника. Початкова фіксація залишається незмінною. Автентифікований доступ до AGY з доступною безоплатною квотою й надалі потрібен; за недоступності або вичерпання квоти слід зупинитися. Запитуваний ідентифікатор моделі залишається `gemini-3.8-flash-low`; оболонка відповіді постачальника не засвідчує незалежно фактично використану модель чи обліковий запис.

Застосунок відповідає за такі обмеження:

- **Відбір одиниць інформаційного пошуку** повторно використовує `RUS-05-v1`: розв’язання **зв’язку походження** відносно наданого джерела передує вміщенню в **бюджет контексту**. Курс задає **бюджет контексту** у 600 символів джерельного тексту; уривки обробляються у фактичному порядку кандидатів. Обмеження не враховує інструкцій запиту, вказівок на місця в джерелі та накладних витрат постачальника; це не 600 токенів і не розмір усього промпту.
- **Перелік доступних інструментів** і надалі містить дві операції з кроку студента 1. Модель може запитати ще одну дозволену **операцію інформаційного пошуку**, запитати **операцію пояснення передумов із використанням моделі** з порожніми аргументами або запропонувати `stop` з порожніми аргументами. Застосунок ніколи не підставляє бажаний вибір.
- Застосунок дозволяє щонайбільше три додаткові рішення вибору дії після першого читання. Кожне рішення викликає щонайбільше одну обрану операцію. Генерування використовує окремий виклик постачальника; пошук виконується локально. Кожен виклик постачальника має п’ятихвилинний тайм-аут AGY і 330-секундний тайм-аут процесу. Автоматична повторна спроба чи виклик для виправлення схеми не запитуються; `useG1Credits: false` залишається обов’язковим.
- Жодна запитувана дія не змінює **канонічної колекції знань**. Згенеровані артефакти робочого простору не є прийнятими знаннями та не надають повноважень запису до канонічних даних.

### Крок студента 2 — Продовжити та інспектувати адаптивну спробу

Із `training-project` виконайте такі команди у Windows PowerShell або терміналі Linux/macOS:

```text
agy models
uv run learning-project lab07 continue-adaptive --first-action-dir reports/lab07/first-read --model gemini-3.8-flash-low --output-dir reports/lab07/adaptive
```

Вихідний каталог можна лише створити, а не перезаписати. Якщо ідентифікатор моделі відсутній, фіксація першого читання відсутня чи неузгоджена або існує будь-який зарезервований вихід, зупиніться та збережіть наявні файли. Не перезаписуйте спробу та не повторюйте виклик моделі, щоб отримати сприятливий вибір.

Відкрийте згенеровані файли в редакторі. Наведені нижче шляхи задані відносно `reports/lab07/adaptive`:

- `attempt.json` зберігає джерельний ресурс, повну фіксацію першого читання, запитувану модель та обмеження застосунку.
- `decision-N/selection-record.json`, де `N` має значення 1–3, фіксує фактичних кандидатів, перевірки допуску, виключення та залишок **бюджету контексту** перед рішенням `N`. Конкретний перший шлях — `reports/lab07/adaptive/decision-1/selection-record.json`.
- `decision-N/request.json` зберігає **обмежений запит до моделі** для вибору дії. Лише допущені уривки з’являються як **надані джерельні свідчення**. Вибрана інформація про завершене читання чи повернення попереднього генерування з’являється як цитовані дані про перебіг завдання всередині **інструкції завдання**, а не як четверте поле чи інший джерельний уривок.
- `decision-N/action.json` і `decision-N/trace.json` розрізняють фактичну запитувану дію, дозвіл застосунку, виконаний вхід і повернення операції. Пропозиція зупинитися чи відхилена дія не мають виконаного входу операції.
- `decision-N/generation/request.json` і `decision-N/generation/outcome.json` існують, коли генерування викликано та видобуто структурно коректний результат. **Обмежений запит до моделі** для генерування використовує ті самі допущені уривки, початкове запитання та успадковані умови цитування/**відмови**, а не всю збережену історію.
- Кожен виконаний виклик моделі зберігає `provider-response.json` і `call-metadata.json` поруч із відповідним запитом. Повна оболонка відповіді постачальника залишається окремою від видобутої дії чи результату; невдалий виклик може не мати видобутого файла.
- `retained-state.json` фіксує початкове запитання, останній виконаний запит, останніх збережених кандидатів, повернення генерування та останні вибрані дані про перебіг завдання. Ці файли разом реалізують **пам’ять агента** для цієї спроби, а не особисте зберігання між сесіями.
- `run-metadata.json` фіксує фактичний статус продовження, кількість нових викликів постачальника та час, що минув для продовження. Вимірювання часу починається після перевірки фіксації попереднього кроку й не враховує попереднього першого читання та людського судження. Неповідомлене споживання залишається невідомим, а не нульовим.

Кожен **обмежений запит до моделі** містить рівно три поля:

- **Інструкція завдання**: початкове завдання та інструкції відповідно до призначення; вибрана інформація про перебіг з’являється лише в запитах вибору дії.
- **Надані джерельні свідчення**: уривки, допущені для поточного виклику.
- **Контракт виходу**: схема дії для вибору дії або успадкована схема пояснення/**відмови** для генерування.

Студент перевіряє такий перелік у порядку читання:

1. Порівняйте кандидатів першого читання з `decision-1/selection-record.json`: кожен допущений уривок зберігає розв’язувану вказівку на місце в джерелі та вміщується в бюджет. Порівняйте допущені ідентифікатори й текст із `decision-1/request.json`; сам збережений кандидатний текст не встановлює передавання.
2. Простежте кожну дію й трасу в числовому порядку рішень. Вибір моделі є спостережуваним наміром наступної дії в межах **планування дій агента**, а не доказом виконання. Перевірте рішення щодо дозволу й виконаний вхід, перш ніж приписувати операцію запитуваному моделлю маршруту. Застосунок виконує **оркестрацію операцій агента**; окремий виклик генерування не є ще одним **агентом**.
3. Коли відбувається генерування, інспектуйте фактичні твердження та **цитування тверджень** або структуровану **відмову** й блокувальну умову. Перевірте будь-який подальший запит вибору дії на наявність цитованого фактичного повернення. Текст генерування є даними про перебіг завдання, а не новими допущеними джерельними свідченнями. Операція на остаточній межі рішень може не мати подальшого запиту; інспектуйте статус обмеження замість твердження про переданий зворотний зв’язок.
4. Прочитайте остаточний статус окремо від відповіді. `stop proposed` означає, що модель не запитала подальшої операції. `application decision limit reached` означає, що застосунок завершив продовження без пропозиції моделі зупинитися. Жоден із цих двох статусів не встановлює виконання завдання. Пізніше студент діє як **оцінювач-людина** за успадкованою **рубрикою оцінювання**; тут `semantic_judgment` залишається `not performed`, а `task_accomplishment` — `not judged`.

Зафіксуйте `02-adaptive-explanation-feedback.png`, показавши запис допуску, фактичний вибір операції, повернення генерування за наявності, подальший запит зі зворотним зв’язком за наявності та остаточний статус. Збережіть знімок екрана й згенеровані файли для подальшого маршруту звіту. Відсутню відповідь чи зворотний зв’язок слід записати явно, а не підставляти приклад.

### Призначення та умови порівняння

Студент порівнює завершену адаптивну спробу із заздалегідь визначеним продовженням того самого завдання пояснення передумови. Фіксований шлях допускає збережених кандидатів читання, один раз викликає **операцію пояснення передумов із використанням моделі** та завершується. Цей фіксований шлях не здійснює керованого моделлю вибору наступної дії, не виконує додаткового пошуку та не запитує рішення за зворотним зв’язком. Порівняння стосується керування рештою операцій, а не нового алгоритму **інформаційного пошуку** чи іншого **агента**.

Обидва продовження використовують той самий завершений `reports/lab07/first-read`, початкове запитання, корпус джерел, дозволи лише на читання, запитуваний ідентифікатор моделі та **критерії допуску одиниць інформаційного пошуку**. **Бюджет контексту** джерельного тексту залишається 600 символів. Обидва шляхи генерування використовують той самий засіб побудови **обмеженого запиту до моделі** відповідно до призначення, контракт цитування/**відмови** та налаштування AGY. Адаптивний шлях може змінити кандидатів через додаткове дозволене читання; будь-яка спричинена цим різниця свідчень належить до виконаного маршруту й має бути записана, а не мовчки усунута.

Студент записує умови порівняння перед фіксованим викликом:

- **Завдання та початкові свідчення:** початкове запитання й точна збережена фіксація першого читання, яку вже використала адаптивна спроба; жоден додатковий уривок не завантажується наперед.
- **Доступні ресурси та дозволи:** незмінний `cases/lab07/accessible-passages.json`, **перелік доступних інструментів** із двох операцій, відсутність записів до канонічних даних і локальні виходи, які можна лише створити.
- **Модель і отримання:** запитувана `gemini-3.8-flash-low`, стандартні налаштування генерування постачальника, `useG1Credits: false`, одна спроба на виклик, відсутність виклику для виправлення чи повторної спроби. Оболонка відповіді не засвідчує незалежно фактично використані модель та обліковий запис.
- **Змінені чинники:** фіксоване проти адаптивного керування, будь-які згодом змінені свідчення, незалежні тривалості викликів і будь-яка спостережувана різниця постачальника чи контексту. Невідомі умови постачальника залишаються невідомими.
- **Межа спостереження:** кожне продовження починається після перевірки того самого збереженого першого читання й закінчується після оброблення результату, перед записом остаточних метаданих запуску. Допуск, очікування постачальника та видобування враховуються. Початкове виконання першого читання, людське судження та звітування не враховуються в жодній із двох тривалостей продовження.

Порівняння є описовим, а не новим бенчмарком цілого завдання чи рішенням щодо вибору конфігурації. Окреме вимірювання тривалості викликів не ізолює причини різниці часу. Поліпшення якості, різниця відповідей чи сприятливий результат не вимагаються. Збережіть попередню адаптивну спробу замість повторного запуску моделі для отримання кращого порівняння.

Використайте завершену адаптивну спробу з кроку студента 2. Із `training-project` виконайте такі команди у Windows PowerShell або терміналі Linux/macOS:

### Крок студента 4 — Оцінити відповіді та інтерпретувати ресурси

Зберігайте основу оцінювання й отримані судження поза кожним запитом моделі. Наведена нижче нумерована процедура оцінювання відповідей дотримується порядку пріоритету з модуля 06; оцінюйте фактичну відповідь кожного маршруту незалежно, а не віддавайте перевагу швидшому маршруту:

1. Ідентифікуйте фактичну відповідь. Інспектуйте `generation/outcome.json` за наявності та необроблену відповідь постачальника, якщо видобування не вдалося. Ідентифікована спроба пояснення з відсутніми полями чи цитуваннями не проходить **перевірку пояснення передумов**; невдале видобування не перетворює цю спробу пояснення на **відмову**. Коли ідентифікованої дозволеної відповіді немає, запишіть збій виконання або відсутню відповідь і зупиніть оцінювання відповіді для цього маршруту.
2. Для **згенерованого пояснення передумов** студент діє як **оцінювач-людина** та застосовує **перевірку пояснення передумов** відносно записаної основи й фактичного допущеного тексту. Запишіть проходження або непроходження та причини для конкретних тверджень, перевіряючи підкріплення цитуванням, а не лише розв’язання вказівки на місце в джерелі.
3. Для **відмови** **оцінювач-людина** застосовує **перевірку відмови** відносно фактичного запиту. Недостатність або конфліктна інструкція джерела мають справді існувати. Коректна **відмова** може залишити запитуване пояснення ненаданим.
4. Окремо запишіть, чи виконано початкове завдання за обмежень дозволів і свідчень, посилаючись на фактичне пояснення або відсутній результат і причину. Ані статус зупинки, ані успішний процес генерування не встановлюють виконання завдання. Автоматизовані метадані залишаються `semantic_judgment: not performed` і `task_accomplishment: not judged`; людські судження студента належать звіту, а не відредагованим файлам середовища виконання.

Для кожного маршруту студент записує такі спостереження ресурсів, зокрема невдалу й незавершену роботу:

- Фактичні додаткові рішення вибору дії, виклики генерування та додаткові виклики локального інформаційного пошуку. Рахуйте пропозицію зупинитися як рішення без виклику інструмента. Виключіть спільне початкове читання та його виклик моделі з підсумків обох продовжень.
- `continuation_seconds` із кожного `run-metadata.json` із використанням оголошеної спільної межі. Записуйте окремі `provider_process_seconds` окремо; сума тривалостей процесів не є тим самим вимірюванням, що час, який минув для продовження.
- Повідомлене `usage` кожної врахованої оболонки відповіді постачальника за наявності. Підсумовуйте `total_tokens` лише коли кожен врахований виклик повідомляє це поле; інакше повідомте часткову суму з кількістю врахованих викликів і позначте повний підсумок як невідомий. Повідомлені постачальником токени не є грошима, відсотком квоти, символами джерельного тексту чи часом людської перевірки.
- Час людського оцінювання — лише якщо його виміряно окремо; інакше запишіть, що він невідомий. Не виводьте нуль із відсутності вимірювання.

Студент пише обмежене порівняння, підкріплене фактичними запитами, відповідями, судженнями та записами ресурсів. Визначте, які рішення ухвалила адаптивна модель і які фіксовані операції були заздалегідь визначені; зазначте, чи надали додаткові вибори відсутній результат у спостереженій спробі. Розкрийте змінені свідчення, різний час виконання та невідомі фактично використані ідентичності. Однакові або однаково успішні відповіді є припустимими спостереженнями. Одна пара не підкріплює загальної переваги, вибору розгортання чи повноважень запису до канонічних даних.

Зафіксуйте `03-fixed-adaptive-comparison.png`, показавши обидва остаточні статуси, фактичні відповіді або їхню відсутність, окремі людські судження за рубрикою оцінювання й щодо завдання та спостереження ресурсів із видимою межею продовження. Збережіть знімок екрана та файли середовища виконання для подальшого маршруту звіту. Звіт завершується на кроці студента 6.

### Призначення

Студент перевіряє три межі застосунку без ще одного платного виклику моделі: запит поза дозволеною областю не має виконуватися, збережений джерельний текст не обов’язково передається наступному запиту моделі, а перерваний виклик має зупинитися, не перетворюючись на відмову чи успішний результат завдання. Команда використовує той самий код дозволів, допуску, побудови запиту й оброблення збоїв, що й адаптивний маршрут, із явно підставленими поверненнями транспорту. Це контрольована діагностика, а не спостереження додаткових живих виборів моделі.

### Крок студента 5 — Перевірити дозвіл, передавання та чесну зупинку

Вхід: завершене перше читання в `reports/lab07/first-read/`. Перед діагностикою команда перевіряє збережену фіксацію відносно незмінного синтетичного джерела. Якщо фактична перша дія не дала `candidates returned`, збережіть фактичний результат і запишіть заблоковане продовження; не замінюйте дію прогнозованим читанням, щоб отримати діагностику, яка проходить перевірку.

Із каталогу `training-project` студент виконує ту саму команду у Windows, Linux і macOS:

```text
uv run learning-project lab07 check-boundaries --first-action-dir reports/lab07/first-read --output-dir reports/lab07/boundaries
```

Вихідний каталог не повинен уже містити `attempt.json`, `summary.json` або будь-якого з трьох діагностичних підкаталогів. Наявні виходи зупиняють команду перед відтворенням входу чи використанням транспорту; студент зберігає ці виходи замість перезапису. Діагностичний збій зупиняє продовження, зберігає завершені файли та вимагає записати спостережену помилку й відсутній результат замість припущення, що перевірка межі пройшла.

Студент інспектує такі випадки за порядком:

1. **Відмова в дозволі.** `denial/decision-1/action.json` містить підставлений запит `canonical write`. `denial/decision-1/trace.json` має показувати `permission.allowed` зі значенням `false`, `executed input` зі значенням `null` і `returned result` зі значенням `null`. `denial/run-metadata.json` має повідомляти `permission denied`. Запит збережено, але жодна операція запису до канонічних даних не існує й не виконується. Відхилення не означає виконання чи незадовільної якості відповіді.
2. **Збережений на відміну від переданого джерельний текст.** Діагностика підставляє дозволений запит інформаційного пошуку, щоб перевірка не залежала від того, чи повернув живий запит обидва уривки. Застосунок виконує локальне читання; другий підставлений вибір пропонує зупинитися. Це контрольоване читання не є додатковим пошуком у порівнянні адаптивного й фіксованого шляхів. `delivery/attempt.json` оголошує контрольований бюджет джерельного тексту у 150 символів, навмисно відмінний від 600 символів нормального порівняння.

   `delivery/decision-2/selection-record.json` допускає AP-1 і виключає AP-2 за успадкованими критеріями допуску. AP-2 залишається в `delivery/retained-state.json`, але його текст має бути відсутнім у всьому `delivery/decision-2/request.json`, зокрема в цитованих даних про перебіг завдання. Студент перевіряє, що `supplied source evidence` у запиті відповідає допущеним свідченням. Повернення зупинки є підставленим; із цього не випливає висновку про наступний вибір живої моделі чи якість відповіді. Не використовуйте цей діагностичний бюджет як третю умову порівняння та не замінюйте попередні фіксації адаптивного й фіксованого шляхів.
3. **Чесна зупинка.** `interrupted/decision-1/provider-response.json` фіксує навмисно підставлений `TimeoutExpired` і контрольоване часткове повернення. `interrupted/run-metadata.json` має повідомляти `execution failure`, один підставлений виклик транспорту й `task_accomplishment` зі значенням `not judged`. Друге рішення, коректна дія чи згенероване пояснення/відмова не створюються. Це не щойно спостережена недоступність постачальника; діагностика перевіряє наявну поведінку зупинки та збереження без автоматичної повторної спроби.

`boundaries/attempt.json` позначає контрольовані діагностичні свідчення та зберігає перевірене перше читання й синтетичне джерело. `boundaries/summary.json` має повідомляти `permission_denial`, `retained_versus_delivered` і `honest_stop` зі значенням `passed`, а `live_provider_invocations` — зі значенням нуль. Зведення з проходженням означає, що три перевірки застосунку поводилися відповідно до специфікації, а не що завдання пояснення виконано чи всю лабораторну роботу завершено. Лічильники у вкладених метаданих описують підставлені виклики транспорту, а не платні виклики постачальника.

Зафіксуйте `04-boundary-checks.png` відразу після діагностичної команди та інспектування. Покажіть відмову в дозволі без виконання, збережений AP-2, пропущений у наступному запиті, підставлене переривання й зведення або фактичну діагностичну помилку. Обліковий запис операційної системи або GitHub і системна дата мають бути видимими. Знімок екрана невдалої розпочатої контрольної точки фіксує збій, а не штучно створює очікуваний результат.

Студент зберігає кожен діагностичний файл і записує у звіті розрізнення між запитом, дозволом, виконанням, передаванням, відмовою моделі та збоєм виконання. Нормальні адаптивна й фіксована відповіді й надалі підлягають незалежному людському оцінюванню за раніше зафіксованою основою порівняння.

Якщо сама команда завершується збоєм до запису зведення, студент зберігає наявний каталог і записує точну команду, помилку, останню завершену перевірку та невиконану роботу. Відсутнє зведення не є проходженням; невдала діагностика не перетворюється на відмову, успішне порівняння чи завершену лабораторну роботу.

### Крок студента 6 — Перевірити, прив’язати та підготувати звіт

Студент завершує звіт за фактичними артефактами й незалежними судженнями перед остаточним комітом. Збережіть усі наявні файли в `first-read/`, `adaptive/`, `fixed/` і `boundaries/`, зокрема необроблені відповіді та невдалі спроби. Для `complete` мають бути наявні всі чотири контрольні точки виконання, людські порівняння й потрібні файли середовища виконання. Завершення звіту не означає, що кожна відповідь моделі пройшла перевірку чи що на початкове запитання надано відповідь. Людські судження про відповідь/завдання залишаються у звіті; ніколи не змінюйте автоматизованих метаданих `not performed`/`not judged`.

Для зупиненого або незавершеного маршруту встановіть `Статус завершення` у `honest-partial`, опишіть точну команду, спостережену проблему, останню завершену дію та відсутні результати в `### Межа зупинки` й збережіть усі наявні файли. Залиште посилання та файли знімків екрана для кожного розпочатого каталогу середовища виконання й остаточної перевірки; видаліть лише посилання для нерозпочатих контрольних точок. Засіб перевірки може підтвердити чесно частковий закомічений запис, не стверджуючи завершення предметного завдання. Повторний запуск моделі чи заміна фіксації не потрібні, щоб частковий запис виглядав повним.

Перед остаточним комітом звіт-джерело описує призначення остаточної перевірки й посилається на її окремі майбутні JSON та зображення; не прогнозуйте успішного результату. На обох платформах перевірка звіту виконується перед додаванням до індексу:

```text
uv run learning-project lab07 validate-report --report-dir reports/lab07
git diff --check
git status --short
git add reports/lab07
git commit -m "Complete Laboratory 07 report"
```

Продовжуйте лише після проходження перевірки звіту-джерела. Студент комітить звіт-джерело, знімки досягнутих контрольних точок та всі наявні машинні свідчення. Належний курсу `cases/lab07/accessible-passages.json` має залишатися незмінним і вже відстежуватися в цьому репозиторії. Ніколи не підставляйте дайджест базового стану джерела замість остаточного коміту студента.

Windows PowerShell — перевірити точну поточну вершину гілки:

```powershell
$finalCommit = (git rev-parse HEAD).Trim()
uv run learning-project lab07 verify --report-dir reports/lab07 --final-commit $finalCommit
whoami
Get-Date
```

Linux і macOS — перевірити точну поточну вершину гілки:

```bash
final_commit=$(git rev-parse HEAD)
uv run learning-project lab07 verify --report-dir reports/lab07 --final-commit "$final_commit"
whoami
date
```

Тепер студент інспектує `reports/lab07/verification-report.json` і фіксує `05-final-verification.png`, показавши команду, повний хеш, результат, обліковий запис і дату. Не комітьте цей знімок екрана після коміту чи JSON перевірки та не редагуйте закомічених свідчень після цього. Вихід перевірки створюється лише за його відсутності, без перезапису. Невдала перевірка зберігається як фактична невдача; вона не дозволяє автоматичного повтору чи твердження про успішне завершення.

Успішна перевірка підтверджує структуру звіту-джерела, точну прив’язку до гілки/HEAD, закомічені байти джерела й свідчень і, для `complete`, узгодженість із відтворенням зафіксованих відповідей і контрольованої діагностики лише для читання. Відтворення не робить нових викликів постачальника. Засіб перевірки не оцінює людських суджень про відповіді, не засвідчує незалежно фактично використані постачальника/модель і не доводить виконання завдання. Відсутні зображення, потрібні до остаточної перевірки, невідстежувані чи ігноровані входи, змінені/видалені джерело чи свідчення, неправильні гілка/вершина або неузгоджені фіксації блокують успішну перевірку.

Після остаточної перевірки та її знімка екрана студент використовує спільну команду подання:

```text
uv run learning-project prepare-report reports/lab07/REPORT.md --max-width 1800 --max-height 1800
```

Явні межі у 1800 пікселів зберігають читабельні деталі зображень контрольних точок у межах цього розміру; інспектуйте згенеровану копію перед поданням. Згенерований `reports/lab07/submission/REPORT.md` вбудовує зображення досягнутих контрольних точок. Звіт-джерело зберігає відносні посилання на зображення. Згенерована копія ігнорується спільним правилом проєкту та не комітиться. Якщо пакування завершується збоєм, збережіть точну помилку та не стверджуйте, що самодостатній звіт створено.

## Контрольні запитання

1. Що за обраною в модулі домовленістю робить спостережений маршрут керованим моделлю, а не лише заздалегідь визначеним процесом виконання операцій? Чому повторні виклики моделі самі собою не становлять **багатоагентної системи**?
2. Які фактичні поля розрізняють запитувану дію, дозвіл застосунку та виконану операцію? Чому запит дії не надає повноважень запису до канонічних даних?
3. Яке передане спостереження вплинуло на наступну дію у фактичній спробі? Що залишається невідомим, коли обмеження застосунку завершує продовження без ще одного запиту?
4. Який текст AP-2 було збережено, але не передано в контрольованій перевірці? Чому збережена інформація чи цитовані дані про перебіг не стають автоматично **наданими джерельними свідченнями**?
5. Який застосунок виконує **оркестрацію операцій агента** та яка додаткова користь від координації виправдала б делегування завдання кільком **агентам** за цих обмежень?

## Необов’язкові розширення

- Запропонуйте на папері інше публічне чи синтетичне запитання, визначивши початкову прогалину свідчень, дозволені операції та умову зупинки без зміни наданого корпусу чи ще одного платного виклику.
- Опишіть поділ завдання, який міг би виправдати кількох взаємодіючих **агентів**, зокрема очікувані витрати на координацію та межу дозволів. Реалізація MAS чи розгортання не потрібні.
